Basic Folder Structure

Standard Directory Layout

root-ts-code/
├── package.json # Central dependency versions
├── tsconfig.json # Base TypeScript config
└── modules/
    ├── module-1/
    │   ├── package.json # Template with "*" dependencies
    │   ├── tsconfig.json # Extends generated config
    │   └── tsconfig.gen.json # Auto-generated paths
    └── module-2/
        └── ...same pattern

Generated Configuration Files

  • TypeScript path mapping for module resolution
  • Project reference configuration
  • Basic dependency tracking metadata

Just standard TypeScript workspace setup with some automation to avoid manual configuration.

Adding New Modules

Simple File Operations

  • Step 1: Create new folder in modules/
  • Step 2: Copy package.json template
  • Step 3: Copy tsconfig.json template
  • Step 4: Run configuration refresh command

Template Files

// package.json template
{
  "name": "@dxs-ts/new-module",
  "version": "${project.version}",
  "dependencies": {
    "@dxs-ts/other-module": "*"
  }
}

// tsconfig.json template
{
  "extends": "./tsconfig.gen.json"
}
pnpm build-modules # Refreshes all configurations

Takes about 30 seconds total. Basic file copying and one command.

Translation File Processing

CSV to TypeScript Conversion

  • Translators prefer working with CSV files
  • Script converts CSV to TypeScript modules (en.ts, fi.ts, etc.)
  • Basic static analysis scans source code for usage
  • Generates organized output with unused translations marked

Output Organization

// Generated CSV organization
// Module: gamut-api
  login.button.submit=Submit
  login.error.invalid=Invalid credentials

// Module: eveli-routes
  navigation.home=Home
  navigation.settings=Settings

// Unused translations (commented)
// login.old.message=... // unused - original on line 247

Standard text processing and file conversion. Nothing sophisticated - just automated housekeeping.

Release Process Automation

Two-Phase Release Pattern

  • Prepare Phase: Generate build artifacts and backup files
  • Perform Phase: Publish to npm and restore originals
  • Borrowed from Maven - standard industry pattern
  • Hidden behind single command for convenience
pnpm release-all # Runs both phases automatically

Basic Build Processing

  • Scans for "lib-*" modules designated for publishing
  • Compiles TypeScript, generates declarations
  • Fixes known TypeScript compiler namespace bugs
  • Creates proper package.json with actual dependencies used

Standard build pipeline with some cleanup scripts for toolchain quirks.
